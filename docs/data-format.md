# Формат данных бронирований

Файл `samples/bookings.json` содержит список записей о бронировании аудиторий. Правила взяты из PRODUCT.md (R1–R4).

## Поля записи

| Поле | Тип | Описание | Допустимые значения |
|---|---|---|---|
| id | число | Идентификатор записи | Число, как в примере. Правила уникальности в PRODUCT.md не указаны (вопрос) |
| room | строка | Номер аудитории | Например, "204" |
| date | строка | Дата бронирования | Формат как в примере: ГГГГ-ММ-ДД, например "2026-10-05". Формат даты в PRODUCT.md явно не описан (вопрос) |
| start | строка | Время начала | HH:MM, местное время колледжа для указанной даты |
| end | строка | Время окончания | HH:MM, местное время колледжа; должно быть позже start |
| owner | строка | Владелец записи | Например, "student-a". Правила формата в PRODUCT.md не указаны (вопрос) |
| status | строка | Статус записи | pending, confirmed, cancelled |

## Время и даты
- Время задаётся как HH:MM по местному времени колледжа для указанной даты.
- Время окончания должно быть позже времени начала.
- Переход через полночь не поддерживается (вне учебной области, R4).

## Статусы
- `pending`: запись ожидает подтверждения.
- `confirmed`: запись подтверждена.
- `cancelled`: запись отменена.

## Пересечения (R1)
Аудитория не может иметь два подтверждённых бронирования с пересекающимися интервалами одного дня. Смежные интервалы 10:00–11:00 и 11:00–12:00 разрешены.

## Пример корректной записи
```json
{
  "id": 1,
  "room": "204",
  "date": "2026-10-05",
  "start": "10:00",
  "end": "11:00",
  "owner": "student-a",
  "status": "confirmed"
}
```
